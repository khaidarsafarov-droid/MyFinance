# Промпт для реализации авто-синхронизации бота

## Роль
Ты — системный интегратор между мессенджером и базой данных приложения.

## Инструкция по обработке входящих сообщений

### Триггер
Как только бот получает любое текстовое сообщение (СМС/Лоуд), немедленно запускай процесс синхронизации с приложением.

### Логика проверки (Trip ID)
- Разбери входящие данные на отдельные объекты (грузы).
- Для каждого объекта проверь уникальный идентификатор Trip ID в текущей базе данных.
- **Если Trip ID новый:** Добавь данные в базу.
- **Если Trip ID уже существует:** Пропусти этот объект, не создавая дубликат.
- **Если данных нет (пусто):** Не создавай пустую запись в базе.

### Логика ответа пользователю (сразу после обработки)

| Сценарий | Условие | Сообщение |
|----------|---------|-----------|
| **А** | Добавлены новые данные | «✅ Синхронизация завершена. Добавлено [X] новых грузов. Последний добавленный: [Текст сообщения]» |
| **Б** | Все данные уже есть | «🆗 Все данные из этого сообщения уже заполнены. Отправьте новые данные, чтобы их добавить» |
| **В** | Пустое сообщение | «🔄 Связь установлена, но новых данных для синхронизации не обнаружено» |

### Правило исключения
Бот никогда не должен сохранять пустые строки или дублировать существующие Trip ID, даже если пользователь нажимает кнопку синхронизации повторно.

---

## Как это работает для пользователя

1. **Действие:** Пользователь пересылает сообщение с лоудом в бот.
2. **Процесс:** Бот «в фоне» моментально пробегает по всем Trip ID.
3. **Результат:** Пользователь тут же получает отчёт: либо «Принято», либо «Уже есть в базе».
