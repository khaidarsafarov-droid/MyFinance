# Системный промпт для управления базой данных грузов

## Иерархия: Год > Месяц > День

Данные группируются по принципу матрешки для быстрого поиска.

## Инструкция для обработки данных

### Автоматическая фиксация (Created At)
При добавлении каждого нового груза (лоуда) автоматически присваивается метка `parsedAt` (creation_date). Это неизменяемое поле для истории — никогда не перезаписывается при редактировании.

### Рабочая дата груза (load_date)
Поле `date` в базе — это load_date. По умолчанию равно дате добавления, но пользователь может изменить его вручную (например, если вносит данные за вчерашний рейс). Редактируется в экране Edit Load.

### Логика редактирования
При изменении любого параметра груза (цена, мили, маршрут, дата) обновляется поле `updatedAt` (last_modified). Поле `parsedAt` (creation_date) никогда не перезаписывается.

### Индексация для поиска
Все записи индексированы по `date` (load_date) для быстрого поиска.

### Гибкий поиск по дате
- **Точная дата:** «25.10.2023» или «2023-10-25» в поле поиска
- **Диапазон:** Фильтры «эта неделя», «прошлая неделя», «этот месяц»
- **Относительный:** Фильтр «вчера» — грузы за вчерашний день

## Структура данных (Load)

| Поле | Описание |
|------|----------|
| id | Уникальный ID (совпадает с tripId) |
| tripId | Уникальный ID груза |
| date | load_date — рабочая дата (YYYY-MM-DD), редактируемая |
| parsedAt | creation_date — время добавления (Long), неизменяемое |
| updatedAt | last_modified — время последнего изменения |
| totalRate, totalMiles, pointA, pointB | Основные данные груза |

## Секция «Год»

- **Автоматическая группировка:** При сохранении груза год извлекается из даты (YYYY).
- **Архив по годам:** Вкладка показывает только те месяцы, в которых есть записи.
- **Годовая статистика:** В каждой секции года: количество грузов, общая выручка, общий пробег.
- **Редактирование:** При смене даты груза с 2024 на 2025 запись автоматически переходит в секцию 2025.

## Room `exportSchema=false` risk

`AppDatabase` sets `exportSchema = false`, so Room does **not** emit versioned schema JSON under `schemas/`. Migrations still run from Kotlin code, but CI cannot auto-diff schemas across versions. Before enabling destructive migrations or shipping major schema bumps, turn `exportSchema = true` and commit the JSON exports.
